# 작업 현황판

MJ의 모든 작업(코드·수익화)을 한 화면에 모아 보는 페이지다.

- 주소: https://w37389952.github.io/mj_github_v1/dashboard/
- **공개 페이지다.** 주소를 아는 사람은 누구나 볼 수 있다(검색엔진에는 안 뜬다).
  계정 이메일, 기기 이름, 키, 비밀번호, 개인 블로그 주소, 수익 금액은 **적지 않는다.**
- 내용은 전부 `dashboard/data.json` 하나에 있다. `index.html`은 그리는 일만 한다.
- `main`에 올라가면 `deploy.yml`이 1분 안에 배포한다. JSON이 깨져 있으면 배포가 멈추고 이전 화면이 그대로 남는다.

## data.json 구조

```jsonc
{
  "updated": "2026-09-30T15:10:00+09:00",   // 고칠 때마다 지금 시각(한국 시간)으로
  "projects": [
    {
      "id": "tistory",                  // 영문 소문자. tasks·log가 이 값으로 가리킨다
      "name": "티스토리 유용팁 생활노트",
      "emoji": "📝",                    // 선택. 이 작업을 나타내는 이모지 하나. 없으면 기본값
      "staff": { "name": "팁이", "role": "블로그 담당" },  // 선택. 오피스 방에 앉은 도트 직원 이름·담당. 없으면 기본값
      "group": "수익화",                // "코드" 또는 "수익화"
      "floor": "영상",                  // 선택. 수익화 안의 층: "영상"이면 🎬 영상 층, 없으면 💰 자동화 층
      "studio": true,                   // 선택. 영상 방이면 true. 방은 다른 방과 똑같이 할 일 중심이고, 요청함에서 고칠 작업물을 고를 수 있고 🎞️ 작업물 칸이 더 붙는다
      "status": "운영 중",              // 운영 중 | 진행 중 | 확인 대기 | 확인 필요 | 막힘 | 기획
      "summary": "한두 문장",
      "links": [                        // 선택. 페이지가 있는 것만. 방을 누르면 뜨는 창에 바로가기 버튼으로 뜬다
        { "label": "블로그 열기", "url": "https://..." }
      ],
      "urgent": "한 줄 이유",           // 선택. 적으면 그 방이 비상(경광등·빨간 테두리)이 되고 층 맨 앞에 선다. 풀 때는 지운다
      "decor": { "wall": "#d9645a", "l": "camera", "r": "softbox", "w": "clapper" },  // 선택. 방 벽지 색과 소품(index.html의 PROPS 이름)
      "progress": 40,                   // 0~100, 또는 아래 goal 중 하나
      "goal": { "label": "애드센스 신청까지 글 수", "current": 7, "target": 20 }
    }
  ],
  "tasks": [
    { "project": "tistory", "title": "할 일", "owner": "MJ",      // "MJ" 또는 "Claude"
      "status": "할 일",                                          // 할 일 | 진행 중 | 막힘 | 완료
      "due": "2026-10-05",                                        // 선택
      "term": "장기",                                             // 선택. "장기" 또는 "단기"(기본)
      "done": "2026-09-30" }                                      // 완료일 때만
  ],
  "log": [
    { "date": "2026-09-30", "project": "tistory", "text": "오늘 한 일 한 문장" }
  ]
}
```

## 오피스와 방 페이지

- 오피스는 층으로 나뉜다: ⚙️ 수익화 · 자동화 → 🎬 수익화 · 영상 → 🛠️ 코드. 층 안은 log에 최근 올라온 프로젝트부터.
  수익화 프로젝트는 `floor`로 층을 고른다("영상"). 없으면 자동화 층.
- 방을 누르면 그 프로젝트 전용 페이지(`dashboard/?room=프로젝트id`)로 간다. 단기 할 일(나/Claude), 장기 계획, 이 프로젝트의 한 일 기록 전체,
  끝낸 일, 바로가기 버튼이 나온다. 프로젝트를 data.json에 추가하면 방과 페이지가 저절로 생긴다.
- 방은 프로젝트 특성에 맞게 꾸며져 있다(영상 = 카메라·조명, 쓰레드 = 옷 행거·쇼핑백, 블로그 = 책장 등). 기본값은 index.html의 `DECOR`,
  data.json의 `decor`로 바꿀 수 있다. 없는 프로젝트는 화분 + 화이트보드.
- 급한 방은 프로젝트에 `"urgent": "이유"`를 적는다. 오피스 위에 비상 띠가 뜨고 방에 경광등이 돈다. 급한 일이 끝나면 `urgent`를 지운다.

## 지금 할 일과 장기 과제

현황판은 할 일을 둘로 나눠 보여준다.

- **⚡ 지금 할 일**: 당장 해볼 일. `term`을 안 적으면 여기로 간다.
- **🗓️ 장기 과제**: `"term": "장기"`인 일. 날마다 꾸준히 쌓는 일(예: 일진 70일 기록), 때가 되면 할 일
  (예: 글 20편 쌓이면 애드센스, 출시할 때 할 일), 필요해지면 할 일.
  프로젝트 status가 `"기획"`이면 그 프로젝트의 일은 `term`을 안 적어도 장기로 간다.
  기획 중인 프로젝트의 일을 당장 할 일로 올리려면 `"term": "단기"`를 적는다.

## MJ의 체크 (checks.json)

MJ가 현황판에서 할 일 체크박스를 누르면 페이지가 `dashboard/checks.json`을 main에 바로 커밋한다
(MJ의 브라우저에 넣어 둔 GitHub 토큰으로. 토큰은 저장소에 올라가지 않는다).

```json
{ "checks": { "iljin::폰에서 카카오 로그인 되는지 확인": "2026-09-30" } }
```

- 키는 `프로젝트id::할 일 제목`, 값은 체크한 날(한국 시간). 체크를 풀면 키가 빠진다.
- 체크된 일은 그날은 줄이 그어진 채 보이고, 다음 날부터 목록에서 빠진다.
- **Claude 창은 이 파일을 읽기만 한다.** 여기 있는 일은 MJ가 끝낸 것이니, data.json을 고칠 때
  그 할 일을 `"status": "완료"`, `"done": 체크한 날`로 바꾼다. 체크된 할 일의 제목은 바꾸지 않는다(키가 어긋난다).
- 할 일 목록의 프로젝트 순서는 log에 가장 최근 올라온 프로젝트가 맨 위다. 그래서 log는 맨 앞에 추가한다.

## 올릴 글 박스 (posts)

MJ가 복사해서 직접 예약할 글은 할 일이 아니라 `posts`에 넣는다. 그 프로젝트 방 페이지에 "📝 올릴 글" 박스 칸으로 뜬다.

```jsonc
"posts": [
  { "project": "threads", "date": "2026-10-04", "kind": "일상", "text": "첫 줄\n둘째 줄" }
]
```

- `text`의 줄바꿈은 `\n`. 박스의 복사 버튼이 이 글을 그대로 복사한다.
- MJ가 예약하고 체크하면 checks.json에 `"threads::글 2026-10-04"` 꼴로 남는다. 체크한 날은 흐리게, 다음 날부터 안 보인다.
- 체크된 글은 지우지 말고 그대로 둔다. 같은 프로젝트에 같은 날짜 글은 하나만.

## Claude에게 요청 (requests.json)

MJ가 이 프로젝트 밖의 창(코드 앱의 다른 채팅 등)에서 못 한 요청을 현황판에 남기는 칸이다.
오피스 첫 화면의 "📮 Claude에게 요청"(방을 고르거나 전체), 그리고 모든 방 페이지에 있다.
페이지가 체크와 같은 토큰으로 `dashboard/requests.json`에 바로 커밋한다.

```json
{ "requests": [ { "id": "r…", "date": "2026-10-03T13:40+09:00",
                  "project": "tistory",          // 방 id. ""면 특정 방이 아닌 전체 요청. 없으면 옛 영상 요청(video)
                  "target": "",                  // 영상 스튜디오에서 고칠 작업물 id(선택)
                  "text": "요청 내용", "status": "요청",   // 요청 | 처리 중 | 완료
                  "images": ["dashboard-uploads/2026-10/r…-1.jpg"],  // 첨부 사진(선택). 비공개 저장소 mj_monetization 안의 경로
                  "reply": "Claude가 남기는 한 줄(선택)" } ] }
```

- Claude는 `status`가 `"요청"`인 것을 집어 `"처리 중"`으로 바꾸고, 끝내면 `"완료"`와 `reply` 한 줄을 남긴다.
  못 하는 요청(MJ의 PC나 로그인이 필요한 것 등)은 `"완료"` 대신 `"처리 중"`에 두고 `reply`에 무엇이 필요한지 적는다.
- `told`: 그 프로젝트 창이 MJ에게 "✅ 완료" 소식을 전한 뒤 `true`로 붙인다(같은 소식을 두 번 말하지 않게). 정기 처리는 이 필드를 건드리지 않는다.
- 요청을 지우거나 순서를 바꾸지 않는다. 고칠 때는 최신본을 다시 받아 해당 항목의 `status`, `reply`만 바꾼다.
- 코드 수정이 필요한 요청은 평소처럼 PR로 하고, `reply`에 PR 링크를 적는다.
- `images`가 있으면 처리 전에 꼭 열어 본다. 사진은 공개 저장소가 아니라 비공개 `w37389952/mj_monetization`의 `main`에 있다
  (긴 쪽 1600px JPEG). 사진 내용을 공개 파일(data.json, reply 등)에 옮겨 적지 않는다.
  페이지 토큰에 mj_monetization 권한이 없으면 사진 첨부가 실패하고, 페이지가 그렇게 알려 준다.

## 영상 스튜디오 (videos.json, requests.json)

영상 층의 방들(`"studio": true`: 애니메이션 밴드 `band`, 공포 쇼츠 `shorts`, 남장여자 로맨스 `romance`, 공모전용 `contest`)은
방마다 따로 요청함과 작업물 칸이 있다. Claude와 힉스필드로 만든 영상·이미지 작업을 그 방에 모아 보여준다.
페이지가 힉스필드를 직접 부르지는 않는다(공개 페이지라 키를 둘 수 없다). 요청과 결과만 파일로 주고받는다.

- `requests.json`: 위 "Claude에게 요청"과 같은 파일이다. 요청의 `project`가 그 방 id다(옛 요청은 `project` 없음 = 예전 `video` 방).
  ```json
  { "requests": [ { "id": "r…", "date": "2026-10-02T11:20+09:00", "target": "v1 또는 빈칸(새 작업)",
                    "text": "요청 내용", "status": "요청", "reply": "Claude가 남기는 한 줄(선택)" } ] }
  ```
  Claude는 요청을 처리하면서 `status`를 `"처리 중"` → `"완료"`로 바꾸고 `reply`에 한 줄 남긴다.
  요청을 지우거나 순서를 바꾸지 않는다.
- `videos.json`: Claude가 결과물을 적는다. 새 작업은 맨 앞에 추가한다.
  ```json
  { "videos": [ { "id": "v1", "project": "shorts",             // 어느 방의 작업물인지(방 id)
                  "title": "공포 쇼츠 썸네일 #1", "status": "완료",   // 대기 | 제작 중 | 완료
                  "date": "2026-10-02", "thumb": "https://… 이미지", "url": "https://… 원본",
                  "note": "한 줄 설명", "request": "r…(선택)" } ] }
  ```
  `thumb`, `url`은 https 주소만 보인다. **공개 페이지라 공개해도 되는 작업물만** 썸네일을 단다.
  얼굴이 나오는 사진, 아직 공개 전인 작업은 `thumb` 없이 제목만 적는다.
- 수정 요청을 반영해 새로 만들었으면 기존 항목을 고치지 말고 새 항목을 추가하고, `request`에 요청 id를 적는다.

## 다른 창에 붙여 넣을 안내문

아래를 그대로 복사해서 각 Claude 창에 보내면 된다.

```
앞으로 작업을 마칠 때마다(하루 여러 번이어도 됨) 작업 현황판에 오늘 한 일을 올려줘.

- 파일: GitHub w37389952/mj_github_v1 저장소, main 브랜치의 dashboard/data.json
  (규칙은 같은 폴더 README.md에 있음. 처음 한 번 읽어줘.)
- 올리는 법: main에서 파일을 새로 받아서 고친 뒤 main에 바로 커밋해줘.
  PR은 만들지 마. 커밋 메시지는 "현황판: <프로젝트> 갱신".
  GitHub 도구(create_or_update_file)로 해도 되고, 로컬 저장소면 git pull 후 push.
  push가 거절되면 다시 받아서 내 변경만 얹어 다시 올려.
- 시작할 때와 올리기 전에 같은 폴더의 checks.json을 읽어. 거기 있는 할 일(키 "프로젝트id::할 일 제목")은
  내가 현황판에서 끝냈다고 체크한 거야. 네 작업의 일이면 끝난 걸로 알고, data.json에서 status "완료", done은 체크한 날로 바꿔.
  checks.json은 고치지 마. 체크된 할 일의 제목도 바꾸지 마.
- 내가 말을 걸 때마다 같은 폴더의 requests.json도 읽어(현황판에 남긴 요청. 하루 두 번 자동으로 처리돼).
  project가 이 작업 id인 것 중
  · status "완료"이고 told가 없는 것: 답 맨 앞에 짧게 "✅ 현황판 요청 완료: <요청 한 줄> (<reply>)"로 알려 줘.
    알린 뒤 그 항목에 "told": true를 붙여 main에 커밋(다시 말하지 않게).
  · status "요청"인 것(아직 자동 처리 전): "현황판에 요청 N건 있어요"라고 말하고 처리해.
    처리하면 그 항목만 status "처리 중"/"완료", reply 한 줄, "told": true로 바꿔 커밋.
  requests.json을 고칠 때는 매번 새로 받아 해당 항목만 바꾸고, 지우거나 순서를 바꾸지 마.
- 고칠 것:
  1) log 맨 앞에 {"date": 오늘 날짜, "project": 이 작업의 id, "text": 한 일 한 문장} 추가
  2) 이 작업의 tasks에서 끝난 건 status를 "완료"로 바꾸고 done 날짜 적기, 새로 생긴 할 일은 추가
     (내가 해야 하는 건 owner "MJ", 네가 할 건 "Claude")
     꾸준히 이어 가는 일이나 때가 되면 할 일은 "term": "장기"를 붙여. 당장 할 일은 안 붙여도 돼.
  3) projects에서 이 작업의 status, summary, progress(또는 goal.current)를 지금 상태로.
     열어볼 수 있는 웹페이지 주소가 생겼으면 links에 {"label": 버튼 이름, "url": 주소}로 추가
  4) 맨 위 updated를 지금 한국 시각으로
- 이 작업이 projects에 없으면 새로 추가해. id는 영문 소문자, group은 "코드" 또는 "수익화".
- 다른 프로젝트 항목은 건드리지 마.
- 공개 페이지라서 이메일, 기기 이름, 키, 비밀번호, 개인 블로그 주소, 수익 금액은 절대 쓰지 마.
- 저장 전에 JSON이 올바른지 확인해줘.
```
