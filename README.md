# 서울 신상 레이더

서울에 새로 문 여는 **음식점 전체**(카페 · 한식 · 분식 · 치킨 등)를 매일 자동으로 수집해서
웹 대시보드로 본다. 지역·업종을 여러 개 골라서 볼 수 있고, 월별·기간별로도 추릴 수 있다.

화면은 탭 두 개로 나뉜다.

- **신규 오픈** — 최근 90일 안에 새로 인허가가 난 곳. 첫 화면.
- **간판 교체** — 인허가는 그 전이지만 최근 90일 안에 기록이 바뀐 곳.
  기존 허가를 넘겨받아 상호만 바꾸는 경우가 많아, 인허가일자만 보면 놓치는 신상들이 여기 있다.

`NEW` 표시는 **방문자마다, 그리고 탭마다 따로** 뜬다. 브라우저에 탭별 마지막 열람일을
남겨두고 그 이후 들어온 건에만 표시한다. '간판 교체' 탭을 며칠 동안 누르지 않았다면
그동안 쌓인 것이 한꺼번에 `NEW`로 뜬다. 로그인이나 서버는 필요 없다.

## 지금 바로 확인해보기 (인증키 불필요)

서울 열린데이터광장은 `sample`이라는 공개 샘플키를 제공한다. 요청당 5건 제한이 있지만
파이프라인이 도는지 확인하는 데는 충분하다.

```bash
python scripts/collect.py
```

## 실제 운영

1. [서울 열린데이터광장](https://data.seoul.go.kr)에 회원가입하고 인증키를 발급받는다 (심사 없이 즉시 발급).
2. 저장소 **Settings > Secrets and variables > Actions > New repository secret**에서
   이름 `SEOUL_API_KEY`로 키를 등록한다. 키는 이 화면에만 넣으면 되고,
   코드나 채팅에 붙여넣을 필요가 없다.
3. **Actions 탭 > "업태값 점검 (수동 실행)" > Run workflow**로 소스가 살아있는지 확인한다.
   최신 인허가일자가 최근이면 정상이다. (2026-08-07 기준 확인 완료)

4. **Settings > Pages**에서 Source를 **GitHub Actions**로 바꾼다. 그러면 수집이 끝날 때마다
   대시보드가 자동으로 배포된다.
5. 범위를 좁히고 싶으면 **Settings > Secrets and variables > Actions > Variables** 탭에서:
   - `DISTRICTS` — 자치구 제한 (예: `마포구,성동구,용산구`). 비워두면 서울 전역
   - `UPTAE` — 업종 제한 (예: `커피숍,다방,까페`). 비워두면 전 업종
   - `WINDOW_DAYS` — 며칠치를 볼지 (기본 90)
   - `EXCLUDE` — 목록에서 뺄 체인 (기본값은 `scripts/collect.py`의 `DEFAULT_EXCLUDE`).
     **이름이 그 단어로 시작할 때만** 걸러진다. `씨유`를 넣어도 `메이 씨유`는 남는다
     (뒤에 붙는 경우는 `…점`으로 끝날 때만 함께 처리)

   전부 비워두면 **서울 전역 · 전 업종 · 최근 90일**을 수집한다.
   `WINDOW_DAYS`를 늘려도 **수집 시간은 그대로다.** 어차피 전량을 훑고 나서 거르기 때문이다.

> 인증키는 저장소 Secrets 밖으로 나갈 일이 없어야 한다. 코드에 넣지 말고,
> 채팅·이슈·커밋 메시지에도 붙여넣지 말 것. 노출됐다면 열린데이터광장에서 재발급받으면 된다.

### 워크플로 두 개

| 파일 | 언제 | 하는 일 | 걸리는 시간 |
|---|---|---|---|
| `collect.yml` | 매일 밤 11:30 (KST) + 수동 | 서울시 API 전량 스캔 → `data/` 갱신 → 배포 | 25~30분 |
| `deploy.yml` | `main`에 push할 때마다 | 저장된 `data/`로 사이트만 다시 배포 | 1분 미만 |

화면이나 문서만 고쳤을 때 30분짜리 스캔을 돌릴 이유가 없어서 나눠놨다.
`collect.yml`이 커밋하는 `data/` 변경은 `GITHUB_TOKEN`으로 push되므로
`deploy.yml`을 다시 부르지 않는다 (GitHub이 재귀 실행을 막는다).

수집 시각이 밤 11시 30분인 이유는 원본이 매일 22:17~22:48에 갱신되기 때문이다
(근거: `docs/data-source-findings.md`). 자정 무렵이면 반영이 끝난다.

> ⚠️ GitHub의 예약 실행(cron)은 **기본 브랜치에 있는 워크플로만** 동작한다.
> 작업 브랜치에 머물러 있으면 매일 자동 실행이 되지 않으니 `main`에 병합할 것.

## 구성

| 경로 | 역할 |
|---|---|
| `index.html` | 정적 대시보드. GitHub Pages에 그대로 올리면 된다 |
| `data/latest.json` | **신규 오픈** 탭 — 첫 화면이 읽는 파일 |
| `data/changed.json` | **간판 교체** 탭 — 그 탭을 눌렀을 때만 받아간다 |
| `data/seen.json`, `data/seen-changed.json` | 관리번호 → 처음 발견한 날짜. 방문자별 `NEW` 기준 |
| `scripts/collect.py` | 수집 · 필터 · 신규 표시 |
| `docs/data-source-findings.md` | 데이터 소스 검증 기록 — **먼저 읽을 것** |

## 인스타 검색 버튼

카드마다 `인스타 ▾` 버튼이 있고, 누르면 검색어 후보가 뜬다. 상호에서 업종어
(`커피`, `로스터스`, `카페` 등)와 지점 표기를 떼고, 괄호 안 영문과 법정동을
조합해 만든 것이다. 고르면 인스타그램 검색 결과로 넘어간다.

**계정을 자동으로 찾아주지는 않는다.** 인스타그램은 계정 검색 API를 공개하지
않고(해시태그 조회조차 비즈니스 계정과 앱 심사가 필요하다), 로그인 없이 프로필을
긁는 것은 이용약관 위반이라 자동 판별은 만들 수 없다. 이 버튼이 하는 일은
사람이 매번 손으로 치던 검색어를 대신 만들어 주는 것까지다.

## 알아둘 것

- **인허가일자 ≠ 실제 오픈일.** 신고 후 개업까지 며칠~몇 주 걸린다.
- **실시간 갱신은 불가능하다.** 원본이 하루 단위 배치로 갱신되므로 매일 1회가 실질적 최선이다.
  인허가 등록에서 데이터 반영까지 2~3일 시차가 있다.
- 검색 목록의 "수정일자"는 종료된 데이터셋에도 오늘 날짜로 표시된다. 신뢰하지 말 것
  (자세한 내용은 `docs/data-source-findings.md`).
